# 資料字典與標籤定義 v1

> 文件狀態：Draft v1（可審閱）  
> 子任務：治理產物 A（Data Governance Architect）  
> 唯一依據：糖尿病風險預測輔助專案需求（MVP、資料型態、驗收指標）

---

## 1. 文件目的與範圍

本文件提供可直接進入跨職能會議討論的治理基線，涵蓋：

1. **資料字典 v1（建議欄位模板）**：在真實欄位未提供前，使用可執行模板並以 **[待確認]** 標記未定事項。  
2. **標籤定義 v1**：定義糖尿病風險標籤產生原則模板（時間窗、事件定義、排除條件、切分原則）。  
3. **資料品質門檻草案**：明確區分 Gate 必須項（Must）與建議項（Should）。

> 限定前提：資料來源為去識別化 CSV，約 5 萬筆；MVP 包含資料上傳、前處理、風險分數推論、結果解釋、報表匯出；需保留審計日誌。

## 2. 資料字典 v1（建議欄位模板）

### 2.1 欄位分類與命名原則

- 分類：ID / 人口學 / 生理量測 / 檢驗值 / 病史 / 生活型態 / 時間欄位 / 來源欄位
- 命名建議：`snake_case`，單位可放 metadata，不建議寫入欄位名
- 未確認欄位一律標記：**[待確認]**
- 若欄位可能造成標籤洩漏，預設 `是否可進模型 = N`

### 2.2 資料字典欄位模板（含待確認標記）

| 欄位分類 | 欄位名 | 資料型別 | 單位 | 允許範圍 | 缺值處理策略 | 品質規則 | 是否可進模型 |
|---|---|---|---|---|---|---|---|
| ID | patient_uid | string | NA | 唯一、不可空 | 不可補值，缺值直接拒收 | 唯一率=100%、空值率=0% | N |
| ID | encounter_uid | string | NA | 唯一、可跨病人重複=否 | 不可補值，缺值標記無效列 | 與 patient_uid 組合不可重複 | N |

> 備註：以上欄位為模板，不代表已確認真實資料欄位存在。正式版需在欄位盤點會議中逐欄確認。

### 2.3 欄位可進模型判定原則

1. 直接識別或追溯識別欄位（如 `patient_uid`、`upload_batch_id`）不可進模型。  
2. 標籤生成專用欄位（如 `index_date`）預設不可作特徵。  
3. 會造成目標洩漏之欄位（事件發生後才可觀測）不可進模型。  
4. 高缺值或品質不穩欄位需先通過品質門檻才可納入。

## 3. 標籤定義 v1（糖尿病風險）

### 3.1 預測目標定義

- **任務型態**：二元分類（在指定預測窗內是否發生糖尿病事件）
- **標籤名稱建議**：`label_diabetes_risk`
- **標籤值**：`1` = 發生事件；`0` = 未發生事件

### 3.2 標籤產生原則模板

| 項目 | v1 定義模板 | 備註 |
|---|---|---|
| 索引日 index date | 每位個體選定一個 `index_date` 作為觀測終點 | 避免同人多筆重疊樣本 [待確認] |
| 觀測窗 observation window | `index_date` 往前 T_obs（例：12 個月）[待確認] | 僅使用觀測窗內特徵 |
| 預測窗 prediction window | `index_date` 往後 T_pred（例：6 或 12 個月）[待確認] | 需與產品使用情境一致 |
| 事件定義 | 符合任一條件即事件：診斷碼、檢驗值門檻、用藥規則 [待確認] | 需醫療顧問簽核 |
| 陰性定義 | 在 T_pred 內未達事件條件且追蹤充分 | 追蹤不足樣本需排除 |
| 排除條件 | index 前已確診糖尿病者、關鍵欄位缺失嚴重者 | 細則待產品/醫療確認 |
| 截尾與追蹤 | 追蹤不足者標記 censored 或排除 [待確認] | 不得混入陰性 |
| 多事件處理 | 僅取首次事件；事件後資料不回滲特徵 | 防止標籤洩漏 |

### 3.3 資料切分原則模板

1. **優先採時間切分**：Train / Validation / Test 依 `index_date` 先後切分，避免未來資訊洩漏。  
2. **病人層級隔離**：同一 `patient_uid` 只能出現在單一資料子集。  
3. **分層控制**：維持各子集陽性率相近（允許容差 [待確認]）。  
4. **鎖定測試集**：模型迭代期間不得重複調參使用測試集。

### 3.4 最小可執行標籤一致性檢核清單

| 檢核項目 | 檢核規則 | 通過標準 |
|---|---|---|
| 時序一致性 | 所有特徵時間 <= index_date | 100% 通過（Must） |
| 標籤唯一性 | 每筆樣本僅一個標籤值且不可空 | 100% 通過（Must） |
| 病人隔離 | train/val/test 不可有同 patient_uid | 100% 通過（Must） |
| 事件可追溯 | label=1 必須可回溯至事件證據欄位 | 100% 通過（Must） |
| 陰性追蹤充分性 | label=0 需具足夠追蹤長度 | >= 98%（Should） |
| 陽性率合理性 | 子集間陽性率差異在容忍範圍內 | 差異 <= 20% 相對差（Should） |
| 重現性 | 同版規則重跑標籤結果一致 | 雜湊一致率 100%（Must） |

## 4. 資料品質門檻草案（Gate）

### 4.1 指標與門檻（Must/Should）

| 品質面向 | 指標定義 | 建議門檻 | Gate 等級 | 不通過處置 |
|---|---|---|---|---|
| 缺值率 | 單欄位缺值比例 | `<= 20%`（一般欄位） | Must | 超標欄位不得直接進模型，需補值方案簽核 |
| 缺值率 | 關鍵欄位缺值比例（index_date、label必要欄） | `= 0%` | Must | 批次拒收 |
| 型別錯誤率 | 不符合宣告型別比例 | `< 0.5%` | Must | 超標批次隔離與回補 |
| 值域錯誤率 | 超出允許範圍比例 | `< 1.0%` | Must | 啟動資料清洗與來源回報 |
| 離群率 | 依 robust 規則判定離群比例 | `< 5%` [待確認] | Should | 人工抽查 + 規則調整 |
| 重複率 | 主鍵重複比例（patient_uid+encounter_uid） | `= 0%` | Must | 去重後重算，仍超標則拒收 |
| 資料新鮮度 | data_extract_date 與上傳日差距 | `<= 30 天` [待確認] | Should | 超標需標註低新鮮度風險 |
| 審計完整性 | 每批次治理與標籤流程日誌完整率 | `= 100%` | Must | 無日誌不得進入推論服務 |

### 4.2 Gate 使用方式（MVP）

1. **Must**：任何一項不通過即不得進入模型訓練與線上推論流程。  
2. **Should**：可放行但需在批次報告註記風險，並建立修正追蹤單。  
3. 每次資料上傳均產生品質報告與審計紀錄，保留供稽核。

## 5. 待產品/醫療顧問確認項目（至少 8 項）

1. 糖尿病事件最終臨床定義（診斷碼組、檢驗門檻、用藥條件）採哪個版本。  
2. `T_obs` 與 `T_pred` 的正式期間設定（例如 12m/6m 或 12m/12m）。  
3. index_date 選取策略（首次就診、最近完整檢驗、固定基準日）。  
4. 陰性樣本追蹤充分性的最低要求（最短追蹤長度）。  
5. 妊娠糖尿病病史欄位是否納入，以及性別/族群適用規則。  
6. 生活型態欄位枚舉值標準（吸菸、飲酒、活動量）是否與現行問卷一致。  
7. 各檢驗值單位標準是否統一為 mg/dL 與 %，是否允許自動單位轉換。  
8. 高缺值欄位的可接受補值方法（中位數、多重插補、模型插補）與簽核流程。  
9. 離群處理策略（截尾、winsorize、保留）對模型解釋性的政策偏好。  
10. 資料新鮮度門檻是否固定 30 天，或依來源系統分級管理。  
11. 審計日誌保存期間、查閱權限與合規要求。  
12. AUC 與延遲驗收門檻對應的監控週期與告警門檻。
