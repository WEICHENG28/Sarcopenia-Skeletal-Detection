# RACI 與決策 SLA v1

> 文件狀態：Draft v1 可審閱

## 1. 文件目的與適用範圍

本文件提供 Phase 0 保守路徑可直接會審之治理基線，涵蓋：

1. RACI 矩陣 v1
2. 決策 SLA v1
3. 會議與節奏
4. 驗收對應與 Gate Must Should
5. 待管理層 法遵 技術主管確認事項

適用範圍僅限已知 MVP：

- 資料上傳
- 前處理
- 風險分數推論
- 結果解釋
- 報表匯出

前提資料：去識別化 CSV 約 5 萬筆。  
主驗收約束：AUC 大於等於 0.80 推論延遲小於 500ms 保留審計日誌。

## 2. RACI 矩陣 v1

### 2.1 角色縮寫

| 縮寫 | 角色 |
|---|---|
| PM | PM |
| SA | System Architect |
| DE | Data Engineer |
| MLE | ML Engineer |
| BE | Backend Engineer |
| MOP | MLOps Platform |
| SC | Security Compliance |
| QA | QA |
| CA | Clinical Advisor |

### 2.2 流程 RACI

R 負責執行 A 最終負責拍板 C 諮詢 I 被通知。每一流程均明確標示 R A C I。

| 流程 | PM | SA | DE | MLE | BE | MOP | SC | QA | CA |
|---|---|---|---|---|---|---|---|---|---|
| 需求凍結 | A | C | I | I | I | I | C | C | C |
| 資料字典定稿 | C | C | R | I | I | I | C | C | A |
| 標籤定義定稿 | C | C | C | R | I | I | I | C | A |
| 模型評估 | C | C | I | R | I | C | I | A | C |
| 延遲驗收 | I | C | I | C | R | A | I | C | I |
| 審計日誌驗收 | I | C | I | I | C | R | A | C | I |
| 報表模板定稿 | A | C | I | C | R | I | C | C | C |
| 上線核可 | A | C | I | C | C | R | C | C | I |
| 異常事件通報 | I | C | I | I | C | R | A | C | I |

### 2.3 RACI 使用規則

1. 每一流程僅允許單一 A，避免責任衝突。  
2. 若 R 與 A 由不同角色承擔，A 必須在會議紀錄中完成簽核留痕。  
3. 任何 Must Gate 失敗時，流程自動切入異常事件通報並套用第 3 節決策 SLA。  
4. 變更 RACI 需經 PM 與 SC 共同確認後生效。

## 3. 決策 SLA v1

### 3.1 決策等級與時限 24x7 口徑

本文件時限一律採 24x7 日曆時間。

| 等級 | 影響定義 | 首次回應時限 | 臨時緩解時限 | 正式決策時限 | 升級節點 | 最終拍板角色 |
|---|---|---|---|---|---|---|
| P1 | 直接威脅 Gate 通過或法遵風險重大 | 30 分鐘內 | 2 小時內 | 8 小時內 | 值班責任人 -> PM -> 管理層 | PM 與 SC 聯合拍板 |
| P2 | 影響關鍵品質或時程但可控 | 2 小時內 | 8 小時內 | 24 小時內 | 責任人 -> PM -> SA | PM 拍板 |
| P3 | 低風險變更或優化議題 | 1 個日曆日內 | 3 個日曆日內 | 下次固定治理會議前 | 責任人 -> PM | 對應領域主管拍板 |

### 3.2 情境化決策 SLA

| 決策情境 | 預設等級 | 觸發條件 | 回應與處置時限 | 升級路徑 | 最終拍板角色 | 必要輸出文件 |
|---|---|---|---|---|---|---|
| 法遵風險 | P1 | 出現疑似違反審計保留 存取 去識別化規範 | 30 分鐘內回應 2 小時內提出隔離與保全措施 8 小時內決策 | SC 值班 -> PM -> 管理層 | SC |
| 效能超標 | P1 或 P2 | P95 延遲超過 500ms 且連續超窗 或尖峰恢復失敗 | P1 30 分鐘回應 P2 2 小時回應 24 小時內決策 | MOP 或 BE -> SA -> PM | PM |
| 模型指標未達標 | P1 或 P2 | AUC 小於 0.80 或評估報告有統計失真疑慮 | 2 小時內回應 8 小時內提出替代方案 24 小時內決策 | MLE -> QA -> PM -> CA | PM 與 CA 聯合拍板 |
| 資料品質異常 | P1 或 P2 | 關鍵欄位缺值 型別錯誤 重複率違反 Must Gate | 30 分鐘至 2 小時內回應 同日完成批次去留決策 | DE -> SC -> PM | PM |
| 需求變更 | P3 或 P2 | 變更影響 MVP 範圍 Gate 條件或合規聲明 | 1 日內回應 3 日內完成影響分析 下次 Gate 前決策 | PM -> SA -> 管理層 | PM |

### 3.3 決策紀錄最小欄位

| 欄位 | 必填說明 |
|---|---|
| decision_id | 決策唯一識別 |
| severity_level | P1 P2 P3 |
| trigger_event | 觸發事件與時間 |
| options_considered | 至少兩個方案與風險 |
| final_decision | 最終決策內容 |
| approver | 拍板角色與簽核時間 |
| rollback_condition | 需回滾之條件 |
| audit_ref | 關聯審計或事故編號 |

## 5. 驗收對應 Phase 0 保守路徑 Gate

### 5.1 支撐 Gate 通過方式

本治理文件以責任明確 時限可執行 證據可追溯三個層面支撐 Phase 0 保守路徑：

1. 以第 2 節 RACI 鎖定每個關鍵流程的單一 A，避免簽核模糊。  
2. 以第 3 節決策 SLA 將法遵 效能 指標 資料品質 需求變更納入統一升級路徑。  
3. 以第 4 節固定會議節奏，確保 Gate 前有足夠輸入證據與可審核輸出。  
4. 對 AUC 與延遲與審計保留三大驗收條件建立可追溯決策鏈，降低臨場判斷風險。

### 5.2 Must Should 清單

| 類別 | 等級 | 驗收項目 | 判定標準 | 證據輸出 |
|---|---|---|---|---|
| 治理責任 | Must | RACI 完整覆蓋指定流程 | 九項流程均有明確 R A C I | RACI 矩陣簽核版 |
| 決策時效 | Must | P1 事件時限遵循 | 首次回應 30 分鐘內且有升級紀錄 | 事故時間軸與通報紀錄 |
| 法遵控管 | Must | 法遵風險有最終拍板 | SC 拍板且留存決策欄位完整 | 決策紀錄與審計關聯 |
| 效能控管 | Must | 延遲超標有治理閉環 | 依 SLA 完成分級 緩解 決策 | 告警與決策單 |
| 指標控管 | Must | AUC 未達標有去留決策 | 24 小時內完成方案決議 | 模型評估會議紀錄 |
| 會議節奏 | Must | 三類會議固定運作 | 週期達成率 100% 且產出文件齊備 | 會議紀錄與追蹤表 |
| 治理成熟度 | Should | P2 P3 議題前置收斂 | 議題在 Gate 前完成影響分析 | 風險報告趨勢 |
| 跨域協作 | Should | Clinical 與 Compliance 早期參與 | 高風險議題於 Weekly Risk Review 完成預審 | 預審清單與簽核註記 |

## 6. 待管理層 法遵 技術主管確認事項

1. P1 事件是否一律要求 PM 與 SC 聯合拍板，或可授權值班主管代理。  
2. 法遵風險預設為 P1 是否同意，是否存在可降為 P2 之例外條件。  
3. 效能超標之 P1 觸發條件是否採用連續超窗機制，或需加入絕對錯誤率門檻。  
4. AUC 未達標時是否允許條件式上線，若允許需追加哪些限制。  
5. 資料品質異常批次之去留決策權是否完全由 PM 拍板，或需 SC 共同簽核。  
6. 需求變更若影響合規聲明時，是否強制升級為 P2。  
7. Gate Review 有條件通過之最長改善期限與逾期處置規則。  
8. Incident Triage 是否要求 24x7 值班覆蓋全部角色，或僅 MOP BE 第一線。  
9. 決策紀錄最小欄位是否需新增法規條文引用欄位。  
10. RACI 中上線核可之 A 由 PM 擔任是否同意，是否需改由管理層最終核准。  
11. Clinical Advisor 在模型指標未達標時之否決權範圍是否需明文化。  
12. Weekly Risk Review 產出是否需同步納入管理層例會之固定附件。
